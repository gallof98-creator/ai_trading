## 4. Open problems, not fixed in this audit

- **Finnhub**: by your decision the platform uses only Alpaca, with TradingView-style charts. The Finnhub live adapter exists and passes its tests with a mock server. Finnhub fundamentals and company information are **not implemented**; fundamentals come from the SEC instead.
- **ECB XML**: exchange rates are parsed with the standard library XML parser (ruff S314). Python's expat does not resolve external entities, so the risk is low. Switching to `defusedxml` would add a dependency and was not done.
- **Survivorship bias**: the stock universe is built from today's most active stocks. Validations on their history do not include companies that have since disappeared. This is stated in the backtest documentation; it is not removable without a delisted-stock database.
- **No demonstrated edge**: most setups fail validation on real data. This is a finding about the strategies, not a software defect.

## 5. Security

**No vulnerabilities found.** Verified:

- **Authentication**: all 152 API endpoints refuse a request without a login. A new test (`test_every_endpoint_requires_a_login_and_no_viewer_can_change_anything`) checks every route from the API schema, so a future unprotected endpoint fails the suite.
- **Read-only role**: no endpoint lets a read-only user change anything. The exceptions are marking notifications as read, and two calculations sent as POST (portfolio preview, screener), which change nothing.
- **Dependencies**: `pip-audit` on `requirements.txt` found no known vulnerabilities, and neither did `npm audit` on the frontend.
- **Credentials**: stored encrypted, never returned by the API, and redacted from logs (existing tests). Only the last 4 characters of an Alpaca key ID appear in messages, never the secret.
- **Other protections, existing tests**:
  - CSRF header required for cookie sessions;
  - CORS restricted to the configured origins;
  - rate limits on login and on the API;
  - security headers;
  - production refuses to start without its secrets.
- **Trading safety**:
  - live trading only through the deployment flag plus the confirmation phrase, never through the API;
  - the AI and the Autopilot cannot change the trading mode or the risk limits;
  - an approval sends only the stored proposal, and the browser cannot modify it;
  - expired or drifted proposals are void;
  - risk is re-evaluated at approval, and quantity can only go down.

## 17. Residual risks

- **Exits watched by the platform**: soft stops for fractional shares and crypto, and take-profit targets at Alpaca, work only while the platform runs and receives live prices. A critical alert is raised otherwise.
- **Gaps and fast markets**: an exit can fill well beyond its stop.
- **Order lookups**: an order whose outcome stays unknown blocks new entries on that instrument until the broker answers. This is deliberate, but it can delay trading during a long outage.
- **Exploration mode**: when switched on, it trades setups that failed validation, with an expected negative result after costs.
